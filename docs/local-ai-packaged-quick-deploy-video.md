# local-ai-packaged — Quick Deploy demo plan (video/GIF)

Purpose: a 60-second demo for the email to coleam00 (author of
coleam00/local-ai-packaged — a YouTube creator who watches video, not text),
plus a short GIF for README/landing.

The stack in frame is the **full upstream set**: n8n, Supabase, Ollama,
Open WebUI, Flowise, Qdrant, Neo4j, SearXNG, Langfuse, Caddy (28 services,
generated by `scripts/build-services.py`). RAM plan: 16 GB (the 7B model
alone takes 5–6 GB loaded; reference cloud size — Hetzner cpx42,
8 vCPU / 16 GB).

**Variant for a small Managed server (if the $26 plan is below 16 GB):**
the no-local-models profile — in `.env`: `OLLAMA_CPU_REPLICAS=0` (Ollama off,
LLM through an external API key) or `OLLAMA_CPU_REPLICAS=0` +
`COMPOSE_PROFILES=gpu-nvidia` on your own GPU hardware. Name this profile
explicitly in the letter ("full profile" / "no-local-models profile") so it
matches the video.

**Quick Deploy link** (from the project README, baked image — all images and
Ollama models already on the server, fresh secrets per install):

```
https://try.direct/quick-deploy?source=github&repo=trydirect/awesome-selfhosted-stacker&path=stacker-projects/local-ai-packaged
```

## Stage 0 — preparation (before recording)

1. Dry-run the install (Quick Deploy or
   `stacker deploy --target cloud --force-new`), record the actual time:
   click → all containers healthy, and the server size on screen.
2. Measure and record: the Managed server size at $26 (if < 16 GB — record
   the video with the no-local-models profile or on cpx42), region, deploy
   time (stopwatch), first LLM response time (baked models already in place).
3. Prepare a demo: an owner account in n8n, one visual workflow (webhook →
   LLM → table/messenger); for the no-local-models profile — pre-fill the
   LLM key in `.env` (the key must not appear on screen).
4. Recording environment: fresh browser profile, notifications off, 1080p60,
   no passwords/tokens on screen (use placeholder values).
5. For the measurements keep at hand: `docker ps`, `stacker agent health`.

## Scene 1 — Quick Deploy (0:00–0:10)

1. Open the local-ai-packaged page in the TryDirect catalog (or the link
   above).
2. Click **Quick Deploy** → the Managed Server screen: region, size, domain →
   **Deploy**.
3. Timelapse of the install (speed up x4–x8): statuses in the UI —
   provision → Ansible → containers; a stopwatch in the corner. With the
   baked image the heavy pulls are barely visible — call this out in the
   letter.

## Scene 2 — Health checks (0:10–0:45)

Each check is a short frame with output. Commands on the server (SSH) or the
published ports through a browser:

1. `stacker agent health` (or Status Panel) — all services green.
2. `docker ps --format 'table {{.Names}}\t{{.Status}}'` — all ~28 containers
   Up (healthy) — scroll the list on screen.
3. Caddy UIs (public): `http://<host>:8001` n8n → `curl -fs
   http://localhost:8001/healthz` → `ok`; 8002 Open WebUI; 8003 Flowise; 8005
   Supabase Studio (login `DASHBOARD_USERNAME`/`DASHBOARD_PASSWORD` from
   `.env`); 8007 Langfuse; 8008 Neo4j Browser (`/browser/`).
4. Data layer: `docker exec <qdrant> curl -s http://localhost:6333/healthz`
   → `{"status":"ok"}`; Supabase REST via Kong: `curl -fs
   http://localhost:8004/rest/v1/` → response/401 (listening is enough);
   Neo4j: no need to hit 7687 — opening 8008 and showing the connect screen
   is enough.
5. Ollama (profile with local models): `docker exec <ollama> ollama list` →
   `qwen2.5:7b-instruct-q4_K_M`, `nomic-embed-text` already in place (baked);
   `curl -fs http://localhost:11434/api/tags` from inside the network → JSON
   list.
6. End-to-end value test: open a workflow with an LLM node in n8n →
   **Execute** → show the result on screen; for the no-local-models profile —
   the answer goes through an external API.
7. Perimeter check: `nc -zv <host> 8001` → open; `nc -zv <host> 5432` (and
   11434/6333) → closed: only 80/443/8001 outward per `public_ports`,
   everything else stays on the internal network.

### Run notes (for the final video)

- The Ollama GPU variants did not start (profiles worked) — the `/dev/kfd`
  failures are gone after the CLI rebuild and the snapshot re-bake
- After the deploy the ports had to be added to the firewall manually:
  `stacker cloud firewall add --public-ports 80/tcp,443/tcp,8001/tcp,...`
  (rules take ~1 min to apply); `public_ports` from stacker.yml did not open
  on their own
- curl from the work machine needs `--noproxy '*'` (proxy env is set) — do
  not show this in the video
- `ollama-pull-1` exits on its own (Exited 0) after downloading the models —
  expected behaviour
