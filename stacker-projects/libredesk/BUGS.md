# [FIXED] libredesk: stacker leaves service env uninterpolated + strong password policy

## Status: FIXED / VERIFIED

## Summary
libredesk needs many LIBREDESK_DB__* / LIBREDESK_APP__* env vars with a strict
koanf schema, and stacker does not interpolate every service-level env var, so
the app panicked on missing/empty keys and could not authenticate to the db.

## Resolution (2026-10-11)
- Ship a complete `config.toml` bind-mounted to `/libredesk/config.toml`,
  generated by `scripts/generate-secrets.sh` at pre_build.
- The generated config injects the real DB password and a required
  `app.encryption_key` (`openssl rand -hex 16`).
- Includes every required section (autoassigner, message, notification,
  automation, ai_agent, webhook, ssrf, conversation, sla, rate_limit.*), so no
  koanf panic occurs.

Result: HTTP 200 on `/health`, `Server started at 0.0.0.0:9000`. See
`LOCAL_DEPLOY_SUCCESS.md`.
